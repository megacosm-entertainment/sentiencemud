# Command Invocation Context Guide

## Purpose

Sentience supports dynamic command names and aliases. A command handler may be invoked by more than one base token (for example, `error` and `errlog`).

This guide documents how to access the **actual base command token used by the player** so syntax text and MXP links can match what was typed.

## API

Use:

- `get_invoked_command_name(const CHAR_DATA *ch)`

Declaration:

- `src/interp.h`
- `src/merc.h`

Implementation:

- `src/interp.c`

## Behavior

`interpret()` now records the parsed command token for the current dispatch and restores the previous value when returning.

This provides:

- Post-alias command visibility (after alias substitution has happened in `substitute_alias()`)
- Nested `interpret()` safety (the prior context is restored after inner dispatch completes)

Internal storage is per-character in `CHAR_DATA`:

- `invoked_command[MAX_INPUT_LENGTH]`

## Usage Pattern in Handlers

When generating syntax/help/MXP command links, do this at the top of the command handler:

```c
const char *base_command = get_invoked_command_name(ch);
if (IS_NULLSTR(base_command))
    base_command = "<default>";
```

Then build output dynamically:

```c
printf_to_char(ch, "Syntax: %s <args>\n\r", base_command);
snprintf(cmd, sizeof(cmd), "%s view %d", base_command, id);
```

## Current Scope

- `do_error` is already migrated to use this pattern.
- Most other command handlers still have hardcoded syntax/help strings.

## Incremental Migration Plan

When touching a command for other work, update it opportunistically:

1. Replace hardcoded command literal in syntax/help lines.
2. Replace hardcoded MXP command targets.
3. Keep fallback default command text for safety.

This avoids a high-risk bulk edit while preserving compatibility with dynamic command renames.

## Notes

- This only affects command text generated by handlers.
- Static helpfile content still needs manual updates where desired.
- Dynamic channels and command dispatch behavior are unchanged by this guide.
